## What was decided today

### Architecture — hybrid ESP32 + Pi Zero 2 W

After exploring three architectures (Pi-only, ESP32-only, hybrid), settled on the hybrid:

- **ESP32**: always-on monitor, real-time RF transmit (CC1101), native CAN bus (TWAI), deep sleep at sub-mA
- **Pi Zero 2 W**: 5" HDMI touchscreen UI, map display, web UI for home monitoring, MQTT publisher
- UART communication between them, ESP32 power-gates the Pi via a logic-level AO3401A P-MOSFET

Rationale: the Pi's WiFi + Linux is what makes home monitoring + maps possible. The ESP32's sub-mA deep sleep is what makes 24/7 battery monitoring possible without draining the car. Each does what it's good at.

### Connection: OBD-II only

Single-point connection through the OBD-II port via a passive Y-splitter:
- Pin 16 (+12V, always-hot) → fused 12V input
- Pin 4/5 (GND)
- Pin 6 (CAN-H), Pin 14 (CAN-L) → SN65HVD230 transceiver

Y-splitter keeps the port available for scan tools. No splicing into the car's harness. 15-minute reversible install.

### Compustar trigger: software-synthesized Keeloq RF

The car has a Compustar 1WSHR-PRO FOB (FCC ID 7087A-R762A433) already installed. The brain is somewhere behind the dash but not visually accessible without disassembly.

Instead of finding the brain's hardwire start input, we'll have the ESP32 transmit a valid Keeloq packet over 433.92 MHz via a CC1101 module. Keeloq has been academically broken; with owner-access to the FOB the practical attacks (chip EEPROM read, manufacturer-key databases) make this very feasible.

Plan:
1. SDR capture of FOB transmissions (RTL-SDR Vomeko dongle on hand)
2. URH analysis to identify framing, serial, function codes
3. Extract device key (Flipper Zero database first, PICkit fallback)
4. MicroPython Keeloq encoder driving CC1101

Detailed in [`docs/BOM.md`](../docs/BOM.md). Single-unit scope so the build is reproducible by anyone reading this repo.

**Lessons learned for future agent-driven shopping:**
- Long-running browser-MCP agents (>5min, >30 tool calls) crashed with socket errors twice in this session
- Cart quantity decrements can silently go to zero (and silently remove the line entirely) if the agent miscounts. Verify after each quantity change.
- Multi-agent shared cart sessions lose state visibility — agents reading the cart at different times see different states. Re-audit is required after every batch of changes.
- Amazon's Asurion Protection Plan modal must be dismissed after every add-to-cart or subsequent adds appear to fail silently
- AliExpress sometimes opens product pages in new tabs when clicking thumbnails — navigate directly to product URLs to stay in the assigned tab
- "Find" tool burns context — prefer `read_page` with `filter="interactive"` and small `max_chars`
- **The "$3 ESP32-WROOM-32U" AliExpress listing the agent kept selecting was a variant-selector trap**: the cheap default variant is just the bundled 2.4 GHz antenna, NOT the board itself. The actual board variant on the same listing is buried deeper at $8-12. The user caught this manually before checkout and picked legitimate alternatives. ## Even later — drivers, state machine, Pi daemon

Continued the "keep going" pass through braindump section 11 (hardware-dependent code). Most of it can be written cold from datasheets and unit-tested with mocks — only smoke-testing on real hardware has to wait for parts.

### ESP32 hardware drivers (commit `77e45d5`)

| File | Highlights |
|---|---|
| `esp32/src/lib/cc1101.py` | SPI driver for the TI CC1101 transceiver. Configured for 433.92 MHz async OOK where we bit-bang GDO0 with the PWM-encoded pulse sequence from `compustar.packet_to_pulses`. GC is disabled during transmit so a collection cycle can't stretch a low-pulse. At TE=400µs the per-bit timing has comfortable MicroPython overhead headroom. |
| `esp32/src/lib/ads1115.py` | I2C driver for the 16-bit ADC, single-shot single-ended read with selectable PGA. Includes `raw_to_volts` helper and two's-complement decode. Sized for the 30k/10k battery divider documented in `config.py`. |
| `esp32/src/lib/twai_can.py` | Thin wrapper around `machine.CAN` for OBD-II 500 kbps. Raises a loud `ImportError` at construction if the MicroPython build doesn't include CAN/TWAI — fail at the bench rather than during a drive. Includes a `query_pid()` helper that handles broadcast 0x7DF + 0x7E8..0x7EF response matching. |

All three include CPython fallbacks (no-op `machine`/`I2C`/`SPI` shims) so they import on a desktop for unit testing. **14 new tests pass** (6 cc1101 + 8 ads1115).

### ESP32 state machine (commit `6057252`)

`esp32/src/controller.py` + thin `esp32/src/main.py` boot entrypoint.

States: `MONITORING → STARTING → RUNNING → STOPPING → COOLDOWN`. Persistent Compustar rolling counter saved to flash **before** RF transmit so a mid-burst crash doesn't reuse a counter value the receiver would reject. UART command dispatch handles `start_engine`, `stop_engine`, `set_threshold`, `shutdown_pi`, `ping` with ACKs. Hardware refs injected at construction so the controller is unit-testable without real hardware.

**9 new controller tests pass**: initial state, no-trigger on normal V, sustained low-V triggers state transition + RF + Pi power-on, counter increment + persistence, UART dispatch, stop sequence powers off Pi after grace, unknown commands ack failure.

### Pi daemon + provisioning (commit `ad89a9a`)

Single-process design: Flask main thread + uart-listener daemon thread + mqtt-publisher daemon thread, all share `pi/app/state.py`'s STATE dict under a lock. No IPC needed.

- `pi/app/state.py` — thread-safe STATE + `ESP32_LINK` singleton + `snapshot()` returning a JSON-safe copy
- `pi/app/comms/uart_listener.py` — reads ESP32 messages, dispatches STATUS/OBD/EVENT/LOG into STATE; ESP32-initiated `shutdown_pi` triggers `shutdown -h +1`
- `pi/app/comms/mqtt_publisher.py` — paho-mqtt client publishes snapshot to `<prefix>/state` retained, reconnects on failure, no-ops if paho isn't installed
- `pi/app/display/server.py` — refactored to use shared state, `/api/command` actually forwards to the ESP32 via the link (returns 503 if link not registered)
- `pi/app/daemon.py` — production entrypoint, run with `python -m pi.app.daemon`
- `pi/systemd/vroom.service` — restart-on-failure, output to journal
- `pi/setup/provision.sh` — idempotent first-boot Pi setup: apt packages, paho-mqtt pip install, enable serial hardware, clone repo to `/opt/vroom`, sudoers.d entry for passwordless shutdown, install systemd unit, chromium kiosk autostart pointing at `http://localhost:8000`

**9 new uart_listener dispatch tests pass.**
