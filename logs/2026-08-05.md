# 2026-08-05 — power source decided: OBD-II tap (12 V socket is switched)

Picking the project back up after a gap. One hardware question closed
and the reference diagram it needs is now in the repo.

## Decision: OBD-II pin 16, not the cigarette/12 V socket

The plan had been to try a 12 V accessory socket first and avoid
tapping OBD-II at all. **Tested: the socket is not always-on** — it
dies with the ignition. That kills it for this build: the whole point
is monitoring battery voltage *while the car is parked and off*, so
the supply has to be always-hot.

So the OBD-II tap it is, as originally specced in
[`docs/13-obd2-install.md`](../docs/13-obd2-install.md) — pin 16 is
unswitched battery+ by the J1962 standard.

## Added: OBD-II power pinout diagram

`docs/images/obd2-power-pinout.svg` (+ a 2× PNG for phone use under
the dash). Drawn rather than downloaded — no licensing question, and
it's tailored to this build: it highlights only the two wires v1
actually needs and greys out the rest.

- **Orientation** (the part that's easy to get backwards): looking
  *into* the car's socket, pins **1–8 = top row**, **9–16 = bottom
  row**, both left → right. Pin 16 is bottom-right, diagonally
  opposite pin 1. Verified against an independent CAN-tools vendor
  pinout, not from memory.
- Sanity check on the physical part: CAN-H (6) sits directly above
  CAN-L (14).
- The tap: **pin 16 (+12 V)** → 2 A fuse → TVS → buck V+ ;
  **pin 4 (chassis GND)** → buck V− → common ground.
- Diagram + doc both carry the meter-it-first warning: the socket can
  be mounted rotated behind the trim, and pin 16 is unfused straight
  off the battery.

## Controller reconnect — no action needed

Confirmed from the (gitignored) `secrets.h`: the board joins SSID
**`IoT`**, and that's unchanged. It should rejoin on its own at power-up.
Fallback if that ever stops working is the board's own AP (`ESP32-Volt`
→ http://192.168.4.1/), which also serves `/update`, so the firmware
can be re-flashed without a cable even if the home SSID changes.
