# 2026-06-13 — dashboard: CPU clock + WiFi power-save toggles (fw 2.1), now NVS-persistent (fw 2.2)

Two runtime power/performance controls on the dashboard, both with the
current state shown plainly to the viewer.

## CPU clock toggle (80 / 240 MHz)

- New `POST /cpu?mhz=80|240` sets the CPU clock via
  `setCpuFrequencyMhz()`; only 80 and 240 are accepted (anything else →
  `400`). 80 MHz is the floor that still keeps WiFi alive; 240 is full
  speed. Lower clock = less self-heating and a little less current —
  every mA helps a parked-car monitor.
- Dashboard: a "Power & performance" card with a live **`NNN MHz`**
  readout and a two-button segmented control `[80 MHz | 240 MHz]`. The
  active clock is highlighted (blue). State comes from a new
  `cpu_mhz` field in `/json`, so the highlight tracks the real chip
  even if changed elsewhere.
- The web server keeps serving at 80 MHz — verified by toggling down to
  80 and back over HTTP without dropping the connection.

## WiFi power-saving toggle

- New `POST /wifips?on=0|1` calls `WiFi.setSleep()`:
  - `on=1` → modem-sleep (the STA default; radio dozes between DTIM
    beacons — saves power, adds a little latency).
  - `on=0` → radio always on (snappier, draws more current).
- Dashboard: a clear **ON / OFF badge** (green ON / grey OFF) plus a
  `Turn ON` / `Turn OFF` button. State comes from a new `wifi_ps`
  field in `/json` (read back from `WiFi.getSleep()`), so the badge
  reflects the actual radio state.

## Persistence across reboot / brownout (fw 2.2)

Both toggles now **persist** — important for a device that'll see
brownouts when the car cranks.

- Stored in **NVS** (`Preferences`, namespace `vroom`, keys `cpu_mhz`
  / `wifi_ps`). NVS lives in a dedicated flash partition, so it
  survives power loss; its journaled/wear-levelled writes are
  power-loss safe (a brownout mid-write leaves either the old or new
  value — never corrupt).
- Written on every toggle (`prefs.putUInt` / `prefs.putBool` in the
  `/cpu` and `/wifips` handlers).
- Restored at boot in `setup()`: CPU clock is read and applied
  *before* WiFi (`setCpuFrequencyMhz`); WiFi power-save is applied
  right after `WiFi.begin` (`WiFi.setSleep`). First boot / garbage
  value falls back to 240 MHz / PS-on.
- Untouched by OTA — app-partition flashing never erases NVS, so
  settings survive firmware updates too.

**Verified across a real reboot:** set CPU 80 / PS off, forced a
reboot (re-flash), board came back **80 MHz / PS off** from NVS, then
restored to 240 / on.

- No RF changes: manual remote start still **armed**, low-voltage
  auto-start still **disabled**.
